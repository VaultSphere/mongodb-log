# MongoDB Log Analyzer

供运维人员在个人电脑上离线使用的 MongoDB 日志分析工具。双击启动后，通过本地 Web 页面上传日志，程序流式扫描全部内容并展示慢查询分析结果。

## 核心能力

- 支持 MongoDB 4.2 及之后的结构化 Extended JSON 日志。
- 支持 MongoDB 旧版单行文本日志。
- 支持普通文本文件和 `.gz` 压缩文件，一次可上传多个文件组成一个任务。
- 基于全部慢查询精确统计八个耗时区间，不使用 Top 5000 抽样。
- 永久保存全局最慢 Top 5000 明细，以及 Top 50 查询模式各自最慢的一条独立样本，其余日志只参与聚合。
- 展示失败操作、操作类型、集合、查询模式、执行计划、客户端 IP、CPU、响应量和小时连接数。
- 统计图支持“图表／数据表”切换，指标旁的问号说明含义与统计口径。
- 耗时、均值和占比等小数四舍五入到 3 位；计数和原始日志保持原值。
- 拖动各指标窗口右下角调整宽高，尺寸保存在本机浏览器，下次打开自动恢复；可恢复默认布局。
- 按集合分组的慢查询散点支持框选、时间缩放与恢复；点击后从右侧查看完整日志和字段解读。
- 仅监听 `127.0.0.1:18080`，日志不会上传到外部服务。

## 一键启动

发布包目录必须包含：

```text
mongodb-log-analyzer/
├── mongodb-log-analyzer.jar
└── scripts/
    ├── start.command
    ├── start.sh
    └── start.bat
```

- macOS：首次使用可在终端执行 `chmod +x scripts/start.command scripts/start.sh`，之后双击 `scripts/start.command`。
- Linux：执行 `./scripts/start.sh`。
- Windows：双击 `scripts\start.bat`。

运行要求是 Java 17 或更高版本。启动成功后会自动打开 `http://127.0.0.1:18080`。如果浏览器没有自动打开，可以手动访问该地址。

停止程序时，关闭启动窗口或按 `Ctrl+C`。

## 数据与隐私

应用默认在启动目录的 `data` 下保存任务：

```text
data/
├── tasks-index.json
├── tasks/<task-id>/metadata.json
├── tasks/<task-id>/summary.json
├── tasks/<task-id>/top-slow-queries.jsonl
└── work/<task-id>/
```

上传文件只复制到 `work` 临时目录，分析完成或失败后删除。应用不会修改用户选择的原始日志。普通日志不永久保存原文；慢查询仅保留全局 Top 5000 和 Top 50 模式各自最慢的独立样本，后者保存在 `summary.json` 中。解读根据本地字段生成，不调用外部 AI 服务。

## 查看分析结果

任务列表选择“查看分析结果”。耗时分布统计全部慢查询；查询模式按出现次数排序；散点只展示全局最慢 5000 条。

统计区块默认显示图表，点击“数据表”查看精确数值；点击指标名后的问号了解范围、单位及排序依据。点击散点，右侧详情依次展示字段解读、排查线索、命令、日志记录、属性与原文。“最慢语句”直接展示对应模式的独立最慢样本，不受散点保留范围限制。

查询模式过长时会省略显示，悬浮或键盘聚焦后展示完整内容。指标窗口的宽高布局按指标保存在当前浏览器；更换浏览器或清除站点数据后需重新设置。

Top 50 默认按出现次数降序。点击具体表头可切换升降序，数值按实际值比较，缺失值始终置后。排序只改变已入选的 50 组的展示顺序，不改变后端按次数选取 Top 50 的范围。

结果页会提示解析失败、部分解析和跳过的行数，可展开查看分类。此类任务的统计仅包含有效提取字段。更新版本不会重算历史结果，需要重新上传原日志才能应用新的解析修正。

任务列表点击“删除”，确认后清理该任务的元数据、聚合结果、慢查询原文、独立样本及残留上传副本。用户原始日志和其他任务不受影响。排队和分析中的任务需等结束后再删除；清理失败会保留任务记录，可在解决权限等问题后重试。

历史任务缺少新版统计或独立样本时，页面会明确提示重新上传原日志分析，程序不会伪造缺失结果。

## 耗时区间

固定区间为：`<100ms`、`100ms-500ms`、`500ms-1s`、`1s-3s`、`3s-10s`、`10s-30s`、`30s-60s`、`>=60s`。边界采用左闭右开，分布统计覆盖任务中的全部慢查询。

## 本地构建

需要 Java 17、Maven、Node.js 和 npm：

```bash
mvn clean test
cd web
npm test -- --run
cd ..
mvn package
```

`mvn package` 会安装锁定的前端依赖、构建 Vue 页面并生成 `target/mongodb-log-analyzer.jar`。项目目录中的启动脚本能直接找到该文件；制作给运维人员的目录时，把 JAR 复制到项目根层并保留 `scripts` 目录即可。最终运行不需要 Node.js、MongoDB、Nacos、S3 或网络连接。

## 常见问题

- 提示 Java 版本过低：安装 Java 17 或更高版本，并确保 `java -version` 指向新版本。
- 端口被占用：关闭占用 `18080` 端口的程序后重试。
- `.gz` 分析失败：确认文件确实是 GZip 压缩格式，而不是仅修改了扩展名。
- CPU 图表无数据：日志本身没有 `cpuNanos` 字段，页面会明确提示。
- 页面长时间显示排队：工具使用单工作线程，前一个大任务完成后会自动开始下一个任务。
- 应用在排队或分析期间退出：重启后中断任务会标记失败，可删除该任务后重新上传；不会继续使用不完整副本生成报告。
